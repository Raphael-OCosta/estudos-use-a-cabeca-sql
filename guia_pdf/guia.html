Guia de estudos · ler + praticar

Use a Cabeça! SQL

edição em português — Lynn Beighley

A melhor forma de estudar um livro técnico: ler um trecho e, em seguida, escrever o código com as próprias mãos. Este guia mostra o caminho, do primeiro clique à rotina diária.

1. O método: ler e praticar

Ler sem praticar dá a sensação de que você entendeu. Praticar sem ler vira copiar e colar. Os dois juntos fixam o conteúdo:

1
Leia uma seção no PDF (o caderno diz a página).
2
Escreva a solução do exercício na célula vazia do caderno de praticar/. Errar faz parte.
3
Confira com o gabarito em resolvidos/ só depois de tentar.
4
Resuma nas células com as suas palavras. Se não conseguir explicar, releia.
5
Salve no GitHub (commit + push): seu progresso fica registrado e público.

2. Primeira vez (uma vez só)

1
Abra o VS Code pelo atalho Projetos e Estudos da Área de Trabalho. A pasta deste livro aparece na barra da esquerda.
Você deve ver as pastas praticar/ e resolvidos/.
2
Se aparecer “Do you trust the authors…”, clique em Yes, I trust the authors.
3
Abra praticar/cap01_…ipynb. No canto superior direito, clique em Select Kernel → Python Environments → .venv (Python 3.12) desta pasta.
4
Clique na célula Preparação e aperte Shift+Enter.
Aparece “Pronto.” com a versão da biblioteca.
5
Abra o PDF do livro ao lado (ou em outra tela) na página indicada no topo do caderno.

3. A rotina de 60 minutos

0–5 min
Abra o caderno do capítulo e rode a Preparação. Releia suas anotações da última vez.
5–30 min
Leia a próxima seção no PDF. Teste os exemplos do livro numa célula nova (B cria uma célula abaixo).
30–50 min
Resolva o exercício sem olhar o gabarito. Travou por 10 minutos? Olhe, entenda e reescreva sem copiar.
50–55 min
Escreva o resumo da seção.
55–60 min
Salve e envie para o GitHub (abaixo).

Salvar o progresso no GitHub

1
No VS Code, clique no ícone Source Control (3º da barra esquerda) e escolha o repositório use_a_cabeca_sql.
2
Escreva uma mensagem curta, por ex.: cap03: produto escalar e inversa.
3
Clique em Commit (se perguntar sobre “stage”, responda Yes) e depois em Sync Changes.
No site do GitHub, o repositório mostra o seu commit.
Ritmo sugerido: cerca de 16 sessões por semana até terminar as 491 páginas. Constância vale mais que velocidade.

Particularidades deste livro

O banco de dados: PostgreSQL no Docker

O livro usa MySQL. Aqui o banco é um PostgreSQL num container do Docker, só para estes estudos (porta 5434). Ele é necessário porque os capítulos 4, 5, 11 e 12 usam ALTER de verdade, views atualizáveis, transações e usuários com GRANT, que o SQLite não tem.

1
Abra o Docker Desktop e espere aparecer Engine running.
2
No VS Code, abra um terminal na pasta deste livro (Terminal → New Terminal) e rode docker compose up -d. Isso é preciso só na primeira vez: depois o banco sobe sozinho junto com o Docker.
3
No caderno, rode a Preparação. Deve aparecer Pronto. Esquema cap01 | tabelas: ...

Como escrever SQL no caderno

A célula que começa com %%sql é SQL puro: digite os comandos embaixo dessa linha, cada um terminado por ;. A tabela mostrada é a do último comando. Cada capítulo tem um esquema próprio (cap01, cap02...), que funciona como um banco separado. Errou tudo e quer recomeçar o capítulo? Na Preparação, troque para preparar(N, "praticar", recomecar=True), rode uma vez e volte ao normal.
